# Обычный документ: какие формы в корпусе и что с ними делает разметка

Замер 14.11.2026. Считано по сохранённым разборам прода
(`platform_parser_ingest_queue.parser_payload`, только чтение) — 92 документа,
11 317 фрагментов, самые свежие проиндексированные разборы. Нарезка —
живой чанкер RAG ветки `fix/chunk-structure-aware-20261114` (`fc801890`),
профиль `parser-merged-context.v2`, бюджет `max_chunk_tokens: 768`.

## 1. Формы, которые действительно повторяются

| Что это | Сколько | Разделяет ли это нынешняя граница фрагментов |
|---|---|---|
| Текстовый фрагмент | 10 335 | — |
| **Ярлык отдельным фрагментом, следом текстовый фрагмент с его значениями** | **650** | Разделяет неправильно: подпись и значения в разных фрагментах |
| Ярлык отдельным фрагментом, следом фрагмент без текста (вырезка пустого поля формы), значения — дальше | внутри тех же 650 | Разделяет неправильно; фрагмент без текста потребитель не индексирует |
| Ярлык отдельным фрагментом, следом картинка | 42 | Соединять нечего: у картинки текста нет |
| Ярлык отдельным фрагментом, следом таблица | 15 | Разделяет неправильно, но текст таблицы рисует адаптер RAG — Parser его не отдаёт |
| Ярлык, чьи значения на другой странице | 5 | Переноса через страницу разбор не подтверждает |
| Номер пункта отдельным фрагментом | 1 | Разделяет неправильно |
| Ярлык, за которым идёт текст, но последняя строка фрагмента не ярлык | 1 | Разделяет правильно — не трогаем |
| **Ярлык и его значения в одном фрагменте** | **1** | Разделяет правильно — не трогаем |
| Фрагмент-таблица | 676 | Разделяет правильно (таблица — своя единица) |
| Фрагмент-чертёж | 159 | Своя разметка (`core/drawing_record.py`) |

Главный вывод замера: **подпись и её значения в одном фрагменте — это
исключение (1 случай), а не правило (650)**. Поэтому разметка частей внутри
фрагмента сама по себе ничего бы не дала: резать между подписью и значениями
нечего, они и так в разных фрагментах. Сначала их надо соединить.

Реально повторяющиеся подписи корпуса: «Знак поверки:» (48 чанков-заголовков
из 226), «ФИФ ОЕИ:», «с применением эталонов:», «Примечания:», «Внешние
условия:», «Вид измерений:», «Имеется:» / «Должно быть:», «РАЗРАБОТАЛ:»,
номера пунктов вида «4.8.3».

## 2. Что модуль выдаёт

`core/document_parts.py`, флаг `DOCUMENT_PARTS_MARKUP` (по умолчанию выключен):

1. соединяет фрагмент-ярлык со следующим текстовым фрагментом той же страницы
   и того же раздела — 691 соединение на 11 317 фрагментах;
2. ставит соединённому фрагменту `record_parts` по контракту чанкера.

Отказы перечислены в `README.md` (строка флага) и в
`docs/PARSER-CONTRACT-CHANGES.md`.

## 3. Замер «заголовок без значений»

Чанк считается заголовком без значений, если его последняя непустая строка —
ярлык по образцам самого чанкера (`_LABEL_ONLY_LINE`, `_NUMBER_ONLY_LINE`).

| | заголовков без значений | из них обычный текст | чанков | символов |
|---|---|---|---|---|
| `structure_aware_chunking` выключен | 226 | 225 | 5329 | 1 519 564 |
| только правила чанкера (без разметки) | 120 | 119 | 5310 | 1 519 583 |
| плюс `DOCUMENT_PARTS_MARKUP` | **26** | 25 | 5272 | 1 519 621 |

Чанков меньше, чем было до флага. Символов больше ровно на число добавленных
переводов строки (+57 к выключенному чанкеру при 691 соединении — часть
соединений попала в чанки, которые и так склеивались).

### Что осталось в 26

* 15 — подпись перед таблицей. Строку таблицы рисует адаптер RAG из
  `table_data`; в тексте фрагмента её нет, и Parser тут бессилен. Сюда же
  относится `total_row:` в конце нарисованной таблицы.
* 4 — подпись, которую разбор признал **заголовком своего раздела**
  (`section_title` равен тексту фрагмента), а следом идёт заголовок соседнего
  раздела. Соединять два заголовка нельзя: это не подпись и её значения.
* 3 — строки записи чертежа и колонтитулы сканов, кончающиеся тире: ложное
  срабатывание образца ярлыка. Соединять там нечего.
* 4 — одиночные случаи (подпись перед фрагментом чертежа, подпись в самом
  конце документа).

## 4. Потерь нет

Три проверки, все на тех же 92 документах:

1. окна каждого родительского фрагмента покрывают `[0, len(text))` без
   зазоров — та же проверка, которую делает чанкер (`_covers_whole_source`);
   нарушений 0 во всех трёх прогонах;
2. текст документа без пробелов совпадает до и после соединения — расхождений
   0 из 92;
3. при выключенном флаге фрагменты совпадают посимвольно (сравнение
   `model_dump`) — 92 из 92, и `apply` возвращает тот же список.

## 5. Замечание к разметке записи чертежа

У ветки `fix/drawing-record-text-20261114` (`28ebcee`)
`core/drawing_record.py::_part_index` оставляет между частями зазор в два
символа: `end` части равен `cursor + len(body)`, а следующая часть начинается
с `cursor + len(body) + len(_JOIN)`. Чанкер проверяет `start != cursor` и
отбрасывает такую разметку целиком (`_record_parts` возвращает `None`),
то есть записи чертежа сейчас нарезаются по-старому. Проверено прямым
вызовом их `_part_index` на двух частях: `end` первой — 28, `start` второй —
30, текст длиной 49. Починка — одна строка: отдавать пустую строку
предыдущей части, `"end": следующий start`, как это делает их собственный
тестовый помощник `_parts_markup`. Здесь это не правится: файл чужой.

## 6. Чем мерить заново

Корпус выгружается `COPY (… parser_payload …) TO STDOUT` только на чтение;
замер — скриптом, который прогоняет `core/document_parts.apply` по
сохранённым фрагментам и отдаёт их чанкеру RAG. Локально взят
детерминированный токенизатор «три символа — токен» (файлов bge-m3 на машине
нет): все три прогона считаются одним и тем же приближением, поэтому
сравнимы между собой; абсолютные числа на проде будут другими.
